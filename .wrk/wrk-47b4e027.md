## Outcome

Select the same existing project from anywhere on disk for serve and ordinary ticket commands.

## Contract

Implemented invocation: wrk list --project /path/to/project (and equivalent selectors on new/show/update/validate). Future serve invocations: wrk serve --project /path/to/project; wrk serve --config /path/to/project/.wrk/config.yaml.

Without a selector, preserve nearest-.wrk discovery starting at cwd. --project names the exact directory containing .wrk; it does not silently discover an outer project. --config names an existing .wrk/config.yaml and selects its owning project, not settings to apply to the launch directory. Arbitrary separate config/data layouts are outside this batch.

## Acceptance criteria

- [x] Add mutually exclusive --project and --config selectors to new/list/show/update/validate and expose reusable resolution for serve; support selector flags before or after the command consistently.
- [x] Resolve relative selectors against invocation cwd; print/report the selected absolute project root using the existing output contract.
- [x] Explicit selection overrides cwd discovery. Reject missing/invalid selected targets without fallback or initialization.
- [x] Preserve the nearest invalid-boundary behavior and current symlink/nonregular-file protections; document canonical-path and symlink behavior.
- [x] Help/version/upgrade remain independent of project discovery. Keep init's existing target-directory behavior and reject unsupported selectors on commands that do not use them.
- [x] Keep relative --body-file inputs relative to invocation cwd, independently of the selected project.
- [x] Test nested and unrelated launch directories, two projects, spaces/relative paths, selectors before/after commands, conflicts, invalid/missing targets, and mutation isolation.
- [x] Update CLI help and configuration/CLI docs.

## Implementation context

The original internal/project/discover.go and internal/cli/args.go/run.go discovered solely from cwd. The new shared resolver preserves that default and adds explicit selection without changing process cwd or storage layout.

## Implementation progress (2026-10-08)

- Added shared `project.Selection`/`project.Resolve`, used by all five data commands and available for the future server. Explicit resolution selects a boundary; callers still load/validate config and tickets through the existing read/store paths.
- Selector parsing is position-independent around the command; conflicting, repeated, empty, missing, and unsupported selectors fail before project access. Command help skips resolution.
- Preserved lexical absolute-path behavior: directory aliases are allowed and retained in `project_root`; `.wrk` symlinks and symlink/nonregular config/ticket files remain rejected. Relative body input stays anchored to invocation cwd.
- Focused parser/resolver and compiled-CLI integration tests pass, including project isolation and no fallback. CLI help, README, configuration/CLI docs, and the docs index now describe the contract.
