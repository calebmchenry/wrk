## Outcome

Discuss a small web interface over existing .wrk files and organize the next feature batch. Discovery and ticket organization are complete; product implementation has not started.

## User intent

Serve a web app reflecting .wrk items, allow a chosen port and an explicit configuration/project elsewhere on disk, and use sensible current-directory defaults. Keep the workflow small: create items, change status, link items, parent items, and tag them.

## Existing foundation

- Current CLI discovers the nearest .wrk from the working directory upward; an invalid inner boundary never falls through to an outer project.
- Creation, status, labels, parenting, and directed dependencies already exist. General related-item links and CLI body updates do not.
- Configuration currently lives at .wrk/config.yaml. Store operations accept a project root and use shared validation and serialized publication.
