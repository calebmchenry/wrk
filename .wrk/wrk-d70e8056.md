## Outcome

Make the local web workspace a compact, table-first interface: query work, browse its hierarchy, inspect and edit an item beside the table, and create items with minimal interruption. Simplicity and efficient vertical space are the primary design constraints.

## Authorization and source

On 2026-10-09 the user accepted the UX direction and recommendations in [wrk-14ac1a9c](wrk-14ac1a9c.md) and requested one parent with implementation children and dependency edges. This records the agreed backlog; implementation progress is recorded below. The original local-workspace milestone [wrk-a1561423](wrk-a1561423.md) is complete and remains historical context.

## Shared product contract

- Put compact query controls and fuzzy title search above a dense hierarchical table. Fit project identity, connection state, filters, search and New into a compact header/toolbar area; use wrapping only when needed. Avoid large branding, persistent help paragraphs, empty detail placeholders, and separate normal-state status banners.
- Use one-line rows: expand/collapse chevron when applicable, compact editable status, title with most of the width, capped tag chips, muted ID and an overflow menu. Children are slightly indented. Keep full values accessible when visually truncated.
- Use the word Tag in the browser; it maps to existing labels and CLI --label without a storage/schema rename. Default to Active; retain All, Ready and explicitly Blocked views. Multiple tag filters use exact AND semantics. Under means descendants excluding the selected root, matching CLI --under.
- Show ancestors needed to explain matching descendants as muted context, not as matching results. During explicit search/filter exploration reveal matching paths despite prior collapsed state, and restore manual expansion state when that exploration ends. The default Active view alone must not prevent ordinary collapse/expand. An Under root can appear as context but does not count as a result.
- Selecting a row opens a right detail panel while preserving a usable table. With no selection, the table fills the available width. Panes scroll independently; close/back preserves selection context and table position. Narrow screens use a full-width detail view with Back.
- New opens a modal with a top-right X, borderless title input, plain description textarea, + Add tag and optional parent chips, and a compact Create action. Only title is required. Use placeholders such as Title and Describe the work, desired outcome, or useful context. No rich Markdown editor or long creation form.
- Add child in the row overflow menu inserts an indented, autofocused title-only draft under that parent. Enter or an inline confirm creates a child, then opens another blank sibling after confirmed success. Cancel/Escape exits. Keep draft input visible through filters and live updates; retain text on errors.
- Details resemble an editable document. Keep title, status, tags, parent and description prominent. Save discrete metadata changes immediately; show compact Save/Cancel only while title/description edits are dirty. Keep children, dependencies, related items and secondary metadata available through compact lower sections/disclosures, including an add affordance when empty.
- Preserve existing capabilities: all five statuses, priority/custom metadata visibility, relationship navigation/editing, safe Markdown display, URL/history navigation, live updates, revision checks, retained drafts, and explicit conflict/uncertain-save recovery. Priority and arbitrary custom-field editing are not required by this redesign; preserve values that are not edited.
- Normal live/saving state uses a small indicator near the relevant control. Actionable errors may expand locally. Borderless inputs still have accessible names and visible focus; interactive row controls must not also trigger row navigation.

## Acceptance criteria

- [x] Compact desktop and narrow-screen layouts give the table primary space and show details without losing navigation context.
- [x] Hierarchy, fuzzy title search, CLI-compatible filters, ancestor context and result counts behave consistently, including closed parents with matching active children.
- [x] Title-only modal creation and repeated inline child creation persist correct items, respect configured defaults, and avoid duplicate submissions or ambiguous retries.
- [x] Row status and document-style detail editing preserve drafts and handle local/agent edits safely.
- [x] Keyboard/focus behavior, field accessibility and actionable error states work across the table, modal, pickers and details.
- [x] Integrated browser/CLI verification, visual inspection and updated agent documentation cover the final UX; all children and this parent's own criteria are reviewed before closure.

## Boundaries

Use the existing local-only embedded app and shared server/store mutation contracts. No new frontend framework or runtime service is required. Rich text editing, boards, drag/drop ordering or reparenting, bulk selection/editing, saved views, new agent controls, accounts and remote hosting are outside this batch. Do not recreate the completed original web milestone or publish a release as part of UX acceptance.
