## Outcome

Change status or add several children directly in the table without opening a long editor or losing the current parent/context.

## Acceptance criteria

- [x] Give each row a compact accessible status control supporting all five existing statuses. Save through the detail editor's shared revision-aware coordination, show success only after confirmation and retain actionable recovery on errors. The control does not trigger row navigation.
- [x] Add Add child to the row overflow menu. Choosing it expands the parent as needed and inserts an indented title-only draft under that parent with autofocus, a borderless accessible Title input, small confirm button and cancel control.
- [x] Enter and confirm submit exactly once; whitespace-only input does not create. Wait for confirmed publication, display the created child and insert/focus the next blank sibling under the same parent. Do not start a new blank row after failed or uncertain creation.
- [x] Escape/cancel removes an empty draft; a nonempty draft is discarded only through an explicit cancel/discard action with the shared dirty-draft protection. Preserve already-created siblings. A missing/deleted parent produces a recoverable error, never silently creates a root item.
- [x] Keep the active draft and necessary parent context visible across filters, collapse requests, sorting/render updates and live polling. Preserve caret, focus and typed text. While the creation session is active, clearly distinguish newly created items outside filters from matching results; restore normal filtering on exit without mutating their tags/status to force a match.
- [x] Create each child with its explicit parent and normal project defaults. Do not implicitly inherit the parent's tags or current query filters. No description is required; details can be edited later.
- [x] Respect the shared single-draft lifecycle when a modal or detail text draft is already open. Status writes coordinate safely with a dirty same-item text draft; changing status so a row leaves filters must not discard an active creation draft.
- [x] Disable repeated submissions while pending, preserve titles on errors, handle parent deletion/validation/BUSY and unknown create outcomes through existing recovery, and never automatically retry an ambiguous create.
- [x] Verify repeated child creation and correct parent through CLI reads, keyboard/cancel behavior, collapsed/filtered parents, live reparenting/deletion/status changes, double Enter, concurrent agent edits and lost responses without duplicate items.

## Dependencies and handoff

Depends on hierarchy/filter rendering for pinned draft/context rows and on detail editing for shared immediate-status/revision coordination. The detail child transitively supplies modal/picker/draft foundations. This explicit sequence avoids building competing save paths for the same item.

## Starting points

internal/web/assets/app.js, model.mjs, editor.mjs and live.mjs; existing create/status browser tests and mutation outcomes.

## Verification and remaining work

Implemented and verified on macOS with Chromium. Inline creation uses the hierarchy's persistent mount,
explicit parent IDs, and omitted optional defaults. Each confirmed create pins the
saved child and clears/focuses the same title input for the next sibling. Escape
only exits an empty draft; explicit Cancel confirms discarding nonempty/uncertain
input. Creation errors retain the title, and ambiguous outcomes require explicit
review before another create. Exiting releases pins and restores ordinary filters
and manual collapse choices.

Row status uses the detail coordinator with captured revisions. Same-item text
edits retain their baseline and input. Row-only writes keep recovery in the table
without taking the creation draft slot. Row selects retain the saved status until
confirmation; conflicts and unknown outcomes retain explicit review/retry/discard
controls in the table. Narrow sessions keep the table visible and use a compact
new* marker with an explanation for created items outside filters.
