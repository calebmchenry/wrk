## Outcome

Find work with a compact query toolbar and inspect it in a collapsible parent/child table without losing matches behind collapsed ancestors.

## Acceptance criteria

- [x] Implement compact Active/All/Ready/Blocked selection, an Under parent picker, removable Tag filter chips, clear filters and a fuzzy title search input. Search/filter controls remain available above the scrolling table.
- [x] Use CLI semantics: exact case-sensitive AND tags; Under includes descendants at every depth but excludes its root; Ready uses todo plus globally completed prerequisites; canceled prerequisites still block; explicitly blocked differs from waiting on dependencies. Display Tag while continuing to read/write labels.
- [x] Replace broad ID/title/body substring matching with deterministic case-insensitive fuzzy title matching. Define the small matching rule and representative fixtures during implementation (for example, ordered noncontiguous title characters); description-only matches must not appear. Keep stable parent-before-child order rather than flattening the tree by relevance.
- [x] Render each displayed item once in its hierarchy with slight indentation, chevrons only where useful, and keyboard-operable expand/collapse. Bound visual indentation for deep trees and avoid recursive traversal that fails on the existing deep-chain fixture.
- [x] Preserve user expansion state during ordinary browsing and live refresh. Explicit search, tags, Under or restrictive Ready/Blocked exploration reveals paths to matches; clearing it restores prior manual expansion. The default Active view alone must allow normal collapse/expand.
- [x] Show nonmatching ancestors only as muted context for actual matches, including closed ancestors. Context rows do not inflate match counts; an Under root is context only, and ancestors above it need not appear. Do not imply dimmed ancestor metadata itself matched the filters.
- [x] Define and verify selection behavior when a selected row is hidden by collapse/filtering. Keep its detail visible with compact context, without forcibly undoing the user's collapse choice. Empty results and missing scope roots provide a clear recovery action.
- [x] Preserve query/selection URLs, browser history and scroll behavior. Document the deliberate search change and change from inclusive parent focus to CLI-compatible Under, including handling of existing focus fragments without crashes or lost selection.
- [x] Add meaningful model/browser checks for filter intersections, a match below a collapsed/closed parent, expansion restoration, counts, live reparenting/status changes and deep hierarchy behavior.

### Implementation and decisions

- Title matching is a trimmed, locale-independent lowercase Unicode character
  subsequence with gaps allowed; internal spaces/repeats are literal. No body/ID
  matching or relevance ranking. Roots/siblings sort by ID in iterative preorder.
- Added the searchable Under picker, removable exact-AND Tag chips and Clear
  filters. Under excludes its root; legacy focus fragments map to Under while
  retaining selection and other query state. Outgoing navigation uses under.
  Unknown tags from fragments remain represented and cannot silently disappear
  when another checkbox is selected. Readiness uses global API blockers.
- Ancestors are context only, including closed ones. Neutral metadata styling,
  visible context labels and accessible descriptions distinguish them from
  matches. Counts exclude context and separately report matches hidden by collapse.
- Explicit exploration holds matching paths open without changing manual choices;
  Active/All alone remain collapsible with keyboard-operable native buttons.
  Choices persist in browser history entries and through reload/live updates.
  Traversal/ancestor closure are iterative; indentation caps at six levels while
  accessible descriptions retain the actual displayed hierarchy level.
- Selection stays open when hidden, with separate collapse/filter explanations.
  Missing scope roots and empty queries have a Clear filters recovery action.
  Query/selection links, pane scroll, live input focus and pending picker searches
  are retained. The toolbar remains above the scrolling table.
- The persistent setInlineChildContext(parentID, createdIDs) mount and model pins
  are ready for wrk-824a1e93. They preserve owned input, selection range and parent
  context without changing match counts or manual collapse state. Child creation
  and status controls remain that ticket's work.
- Updated browser/CLI/README contracts and docs index, including the deliberate
  title-only/Under semantic changes and the insertion-hook handoff. Existing
  unrelated working-tree changes were preserved.
