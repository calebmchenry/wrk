## Outcome

Capture the user's wrk run discussion and organize a small implementation backlog with explicit dependencies, acceptance criteria, and verification.

## Accepted direction (2026-10-10)

- Move query-first sequential command execution into the wrk CLI. Commands and quoted arguments follow `--`; substitute `{id}` inside arguments without implicit shell evaluation.
- Reuse existing list filters and project selection. Execute in the selected project root with the inherited environment and noninteractive input.
- Default success is exit 0; an optional `--expect-status done` adds a persisted-ticket completion check for burns.
- Successfully processed ticket IDs are skipped for the rest of the invocation. This applies across streaming polls; restarting allows them to be processed again. Failed commands and failed completion checks stop the run.
- `--stream` waits and polls when no unprocessed matches are available. Ordinary execution drains available work and exits.
- Provide explicit selection of a single ticket and an actionable retry command. Scripts own recovery from partial work and should be safe to rerun.
- Improve human output with readable filters, selection counts/order, ticket titles, quiet heartbeats, meaningful empty-queue explanations, failure distinctions, logs, and a final report; also support structured JSON events.
- Keep the first version small. Named steps, durable workflow checkpoints, automatic retries, rollback, agent-specific orchestration, and parallel task claiming are outside scope.
