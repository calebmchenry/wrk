## Outcome

Allow existing tickets to change priority and labels through `wrk update`, extending the current creation-time overrides.

## Scope

Define explicit replacement/add/remove/clear semantics for labels and their conflicting flags. Priority uses the existing low/normal/high/urgent vocabulary. Preserve the current schema rule that duplicate labels are not forbidden. Configured defaults continue to affect only new tickets.

## Acceptance criteria

- [ ] Support priority changes through the CLI.
- [ ] Support documented label update and explicit empty-label operations.
- [ ] Combine supported metadata flags into one validated update with clear conflicts and no-op results.
- [ ] Preserve exact bodies, unrelated custom values, omitted fields, permissions, and safe publication guarantees.
- [ ] Verify human/JSON output, invalid input rejection, and default changes that never alter existing tickets.
- [ ] Add meaningful tests on supported platforms and update indexed docs.

## Context

`new --priority`, repeated `--label`, and `--no-labels` already work. Follow [configuration](../docs/configuration.md), [CLI contract](../docs/cli.md), and [storage](../docs/storage.md).

[wrk-d965ba66: Support scoped AI task burns with labels and blocked status](wrk-d965ba66.md)
uses this ticket's single-ticket label mutations. Coordinate the shared add/remove
implementation; the burn ticket adds recursive labeling, scope filters, blocked
status, and the agent workflow. Priority and replacement/clear-label operations
remain in this ticket.

## Shared add/remove implementation completed

wrk-d965ba66 completed the reusable single-ticket `--add-label` / `--remove-label` path, including combination with title/status, no-ops, duplicate preservation, and safe publication. This ticket remains open for priority updates and replacement/clear-label operations; do not implement a second add/remove path. Add/remove overlap is a usage error, removal deletes all matching occurrences, and unrelated labels retain their order and duplicates.


Verified on 2026-10-02: macOS arm64 and Linux arm64 with Go 1.25.4 passed formatting, uncached unit/integration tests, race tests, vet, and build. Shared code is in `ticket.Changes` / `PatchChanges` and `store.UpdateWithOptions`; add/remove accepts title/status in the same validated update. Tests preserve duplicates, omitted fields, exact bodies, custom aliases/tags, modes and no-op inodes, and verify failure semantics. README and indexed CLI/storage/burn docs describe the shipped behavior.

Remaining for this ticket: implement priority and label replacement/explicit clear flags, define their conflicts with existing add/remove flags, and extend the shared patch/update path and its tests. This ticket remains in-progress because its full acceptance criteria are not yet met.
