## Outcome

Make details feel like an editable document, with direct metadata changes and lightweight text editing while the table remains visible.

## Acceptance criteria

- [x] Show title, status, tags, parent and description prominently. Title and plain description textarea are borderless, keyboard accessible and have visible focus. Keep safe rendered Markdown available outside editing without introducing rich text editing.
- [x] Text editing uses a retained title/body draft with compact Save/Cancel only while dirty. Empty description clears the body; an empty title cannot save. Preserve exact untouched description bytes and omit unchanged fields from mutations.
- [x] Status, tag and parent changes save immediately through revision-checked writes; retain all five statuses. Use shared modal pickers and compact pending/saved/error feedback. Reparenting does not change an item's status or propagate changes to children.
- [x] Coordinate immediate metadata writes with a dirty title/body draft, including row status actions. A confirmed local write must not lose typed text or cause a spurious self-conflict; external changes must still fail stale preconditions. Only advance draft baselines for known confirmed own writes or explicit conflict review, never merely because polling supplied a newer version.
- [x] Keep children and direct-child progress, dependencies, reverse dependents, related links, priority and original/custom metadata discoverable in compact lower sections. Allow existing dependency/related add/remove operations from those sections; empty relationships retain a small add affordance. Arbitrary custom YAML remains safely readable and preserved.
- [x] Preserve relationship navigation, closed/out-of-filter targets, copy ID/link, panel close/back and table scroll. Switching selections, starting a modal or beginning inline creation never silently discards or replaces a dirty draft.
- [x] Retain input and display actionable field-local external-change/conflict recovery; explicitly review current values before adopting a revision. Preserve reciprocal-related revision checks and partial/uncertain publication behavior. No silent overwrite or automatic mutation retry.
- [x] Verify immediate metadata persistence, title/body Save/Cancel, empty body, unchanged CRLF/custom values, local metadata changes during a text draft, concurrent CLI edits, relationship cycle errors and retained drafts across navigation/reconnect.

## Scope and handoff

Depends on modal/shared picker and draft primitives, which in turn depend on the panel shell. Own the shared existing-item mutation coordination used by panel and row controls. Preserve existing writable fields and display-only metadata; adding priority editing or a custom-field builder is outside this ticket.

## Starting points

internal/web/assets/editor.mjs, app.js and live.mjs; existing revision-checked mutations and docs/browser.md conflict/recovery contract.

## Verification and remaining work

Implemented the direct document editor in `detail.mjs`, with shared modal pickers,
immediate status/tag/parent/relationship writes, retained text Save/Cancel, compact
field feedback and explicit conflict/uncertain-publication review. `app.js` exports
`changeItemStatus(id, status)` for the row-controls follow-up. `yieldDraft()` guards
New and future inline creation. Confirmed responses alone advance active draft
revisions; subsequent polling cannot adopt an intervening agent write. Text typed
during an in-flight save survives. Pristine views follow polling until input begins.
