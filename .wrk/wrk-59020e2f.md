## Outcome

`wrk run` executes one supplied command for each selected ticket, re-queries after success, and makes a failed ticket easy to retry explicitly. Implement the non-streaming execution path and shared engine used by later tickets.

Read the agreed contract and implementation defaults in [wrk-0a233d21](wrk-0a233d21.md).

## Behavior

- Reuse list's `--ready`, `--all`, repeated AND `--label`, and descendant `--under` filters, including existing conflicts and root exclusion. Reuse `--project`/`--config` discovery and pin the selected project. Query mode without filters uses ordinary active-list semantics; do not hardcode the old burn script's todo/in-progress-only restriction for arbitrary actions.
- Require a nonempty child command after `--`. Preserve child flags, whitespace, empty arguments, and shell metacharacters literally. Replace each literal `{id}` in argument values without splitting or evaluating the result; executable selection itself is not a ticket template.
- Resolve bare executable names through inherited PATH. Execute relative executable paths and child relative arguments from the project root; document that distinction from invocation-relative project/log options. Inherit the parent's environment without sourcing shell startup files or loading .env files. No full environment dump. Close child stdin.
- Use one child at a time, with process-group shutdown on SIGINT/SIGTERM and bounded escalation for descendants that ignore termination. Do not keep the store writer lock while a child runs. Children must be able to use the same project's ordinary wrk mutation commands.
- Re-query the current project after each success. Use deterministic existing ID order and an in-memory set of successfully processed IDs; choose the first current match outside that set. Changes/newly unblocked tickets are visible on the next query. When all matches have been processed, exit successfully even if the raw query remains nonempty.
- Exit 0 is the default action-success rule. `--expect-status <status>` validates a built-in status and adds a same-project/same-ticket persisted-state check after the child exits 0. Missing/deleted/invalid tickets or failed required checks are failures, not successful processing. A ticket becoming in-progress or leaving the query does not satisfy expected done.
- Only add the ID to the processed set and success count after all checks pass. Failed execution/checks stop immediately; do not continue to another ticket or retry automatically. `--max-tickets N` limits positive successful actions, not attempted actions or done-status totals.
- Provide one-off `--ticket <id>` execution for manual retry independently of readiness. It validates the project and ticket and uses the same action/success rules; it does not reset status. Keep this selector separate from query filters and streaming. Re-running starts the supplied action from the beginning with no remembered checkpoints.

## Implementation notes

- Core CLI parsing and help now accept query filters, `--ticket`, `--expect-status`,
  positive `--max-tickets`, and a required child delimiter. Other commands retain
  their argument contracts.
- `internal/runner` owns strict project reads, list selection/requery, per-invocation
  successful IDs, child execution, persisted checks, and lifecycle facts. CLI rendering
  is separate so continuous mode and output work can extend this engine.
- Relative executable paths and relative PATH entries resolve from the project root;
  project/config selectors remain invocation-relative. Only arguments expand `{id}`.
  Child stdin is `/dev/null`; exported environment is inherited without loading files.
- SIGINT/SIGTERM use a separate child process group, SIGTERM followed by bounded
  SIGKILL escalation, including descendants remaining after the leader exits.
- Baseline human progress and explicit retry diagnostics are implemented. `--json`
  currently emits one final envelope with the exact action and failure facts; child
  streams go to stderr. Streaming, durable logs, and lifecycle JSON remain in the
  existing follow-up tickets.
- Targeted parser, engine, and real compiled-CLI tests pass on macOS, including
  fake child mutations, dependency unlocking, unchanged-status actions, argument/env/
  cwd preservation, status mismatch/deletion, and SIGINT/SIGTERM descendant cleanup.
  Full development checks and Linux verification passed; details follow.
